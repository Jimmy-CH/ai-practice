1. 系统简介

内容生产发布工作台帮助内部运营团队将活动主题、产品文档、操作手册等原始资料，一键转化为可直接发布的标准化内容资产。

  • 创建内容项目并设定主题、受众、语气
  • 粘贴/导入产品文档、操作手册等原始资料
  • 一键生成三类资产：公告（announcement）、FAQ（faq）、海报文案（poster）
  • 覆盖式编辑、提交审核、审核者审阅、下载 Markdown/HTML、模拟发布
  • 完整的操作审计日志，确保生成依据可追溯

2. 环境准备

2.1 安装后端依赖

cd content-workbench/backend
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt

2.2 安装前端依赖

cd content-workbench/frontend
npm install

2.3 配置环境变量

复制示例配置文件并填入 DeepSeek API Key：

cd content-workbench/backend
copy .env.example .env

编辑 .env：

DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
LOG_LEVEL=INFO
提示：pydantic-settings v2 不会自动读取 .env，项目已在 app/config.py 中显式声明 env_file 加载路径。

3. 启动服务

3.1 真实生成模式

# 终端 1：启动后端
cd content-workbench/backend
$env:DATABASE_URL="sqlite+aiosqlite:///./workbench.db"
.\venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 终端 2：启动前端
cd content-workbench/frontend
npm run dev

访问地址：

  • 前端：http://localhost:5173/
  • 后端 API 文档：http://127.0.0.1:8000/docs

3.2 测试/演示模式（不调用真实 DeepSeek）

使用专用 E2E 入口，自动注入 FakeGenerator：

cd content-workbench/backend
$env:DATABASE_URL="sqlite+aiosqlite:///./e2e.db"
.\venv\Scripts\python.exe -m uvicorn app.e2e_main:app --host 127.0.0.1 --port 8000
注意端口占用：如果 8000 端口出现幽灵占用（netstat 显示 LISTENING 但无法连接或 taskkill 找不到进程），请改用 8001，并同步在前端 frontend/.env.local 中设置 VITE_API_TARGET=http://127.0.0.1:8001，然后重启 vite dev server。

角色 用户名 密码 权限
编辑者 editor editor123 创建项目、添加资料、一键生成、编辑资产、提交审核、下载 approved 资产、模拟发布

5. 完整业务流程

1

创建项目

使用 editor 登录，进入「项目中心」，点击「新建项目」，填写项目名称、主题、受众、语气。

2

添加资料

进入「资料中心」，输入资料名称和正文，点击「添加资料」。可添加多条资料，系统会自动按内容哈希去重。添加完成后可点击「查看」预览原文，点击「进入工作台」跳转。

3

一键生成

在创作工作台点击「一键生成」，系统会读取该项目下全部资料，从中筛选最相关的片段作为证据，生成 announcement、faq、poster 三类资产。

4

编辑与提交审核

编辑者可对 draft 资产进行覆盖式编辑，满意后点击「提交审核」。资产进入 pending_review 状态后禁止再次编辑；approved 资产若被再次编辑，状态会自动回落为 draft。

5

审核与发布

使用 reviewer 登录，进入「审核与交付」查看待审列表，查看资产内容及引用来源后选择「通过」或「驳回」。审核通过后，编辑者可下载 Markdown/HTML 或创建模拟发布任务。

6. 多资料生成机制

当用户提交多个资料时，系统不会只使用某一个资料，而是从所有资料中挑选与项目主题/受众最相关的若干片段：

  1. 遍历项目下所有资料
  2. 将每条资料按空行、句号、感叹号、问号切分成片段
  3. 过滤掉长度小于 5 个字符的片段
  4. 用项目 theme 和 audience 作为关键词，统计每个片段命中关键词的次数
  5. 只保留命中次数大于 0 的片段，按分数从高到低排序
  6. 取前 max_evidence_chunks 条作为最终证据，交给大模型生成
提示：资料越多、相关片段越丰富，生成结果的可信度越高；但如果所有资料都没有命中项目主题或受众关键词，系统会拒答。

7. 常见问题：提示缺少资料

7.1 项目下没有任何资料

错误信息：该项目暂无资料，请先添加资料后再生成

解决：在资料中心添加至少一条资料。

7.2 资料与项目主题/受众不相关或内容过短

错误信息：现有资料与项目主题/受众不相关或内容过短，请补充相关资料

触发原因：

  • 资料正文没有包含项目的 theme 或 audience 关键词
  • 资料片段长度小于 5 个字符，被检索过滤
  • 资料内容虽然相关，但措辞与主题/受众关键词不匹配

解决：

  • 在资料中明确写出项目主题词和受众词
  • 避免只粘贴过短的片段
  • 确保资料正文与项目设定高度相关

8. 快速生成测试数据

8.1 一键生成完整演示数据

在测试模式下启动后端后，运行脚本：

cd content-workbench/backend
$env:WORKBENCH_API_URL="http://127.0.0.1:8000/api"
.\venv\Scripts\python seed_demo_data.py

该脚本会自动完成：创建项目 → 添加资料 → 一键生成 → 提交审核 → 审核通过 → 模拟发布。

8.2 API 测试数据示例

文件 content-workbench/backend/test_data_sample.json 提供了可直接用于 Postman 或 curl 的测试数据，包括：

  • 可正常生成的项目与资料
  • 资料不相关、无资料、资料过短等拒答场景
  • 登录、创建项目、添加资料、一键生成的完整请求模板

9. 测试与验证

9.1 后端单元测试

cd content-workbench/backend
.\venv\Scripts\python.exe -m pytest tests -v

当前基线：45 passed。

9.2 前端构建

cd content-workbench/frontend
npm run build

构建成功会输出 dist/ 目录。

9.3 注意事项

  • 资料按内容哈希去重，重复提交相同内容会返回 409
  • 仅 approved 状态的资产允许下载和模拟发布
  • 无足够证据时系统会拒答并返回 422，不会产生半成品资产
  • 所有关键操作均记录审计日志
  • 开发调试时可使用 app.e2e_main:app 入口避免真实 LLM 调用
