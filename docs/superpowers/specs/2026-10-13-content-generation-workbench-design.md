# 内容生产发布工作台需求分析设计

> 日期：2026-10-13　状态：已与需求方逐节确认　定位：独立需求分析报告（不依赖任何既有实现）

## 1. 需求背景与目标

产品发布（新品上市、版本更新、功能上新）需要产出公告、FAQ、海报等多形态内容。现状痛点：撰写重复劳动多、跨形态改写费时、AI 生成内容事实错误难发现、产出-审核-发布流程松散无留痕。

目标：为内部运营团队构建 AI 内容生产工作台——输入活动主题与产品资料，一键产出结构化、有依据的公告/FAQ/海报文案，经人工审核后导出或交付发布，全程合规可控。

一句话需求：输入活动主题、产品文档、操作手册等，一键产出公告、FAQ、海报，可修改、下载；生成内容人工审核后发布，合规可控。

## 2. 目标用户与角色

| 角色 | 职责 | 关键操作 |
|---|---|---|
| 内容编辑（editor） | 准备资料、触发生成、修改润色 | 建项目、贴资料、生成、编辑 |
| 内容审核（reviewer） | 质量与事实把关 | 查看引用依据、通过/驳回 |

角色分离是硬性要求：同一账号不可同时承担生成与审核两类操作，接口层强制校验。

## 3. 核心用户故事

1. 作为编辑，我创建发布项目（主题/受众/语气），粘贴产品文档和操作手册，系统对资料按哈希去重入库。
2. 作为编辑，我点击"一键生成"，系统按内容类型专属结构产出公告、FAQ、海报文案，每条内容附依据来源引用；资料不足时明确拒答，不编造事实。
3. 作为编辑，我可直接修改任何生成结果并保存（覆盖式）；已审核通过的内容一旦再编辑，状态自动回落为草稿，必须重新审核。
4. 作为审核者，我逐条查看内容及其引用的证据片段原文，通过或驳回（附意见）。
5. 作为编辑，仅审核通过的内容可下载为 Markdown/HTML，可创建发布任务（模拟渠道）。
6. 作为管理员，所有关键操作（生成/编辑/审核/下载/发布）留有审计日志可查。

## 4. 功能需求

### FR-1 项目与资料管理
- 创建发布项目：活动主题（必填）、目标受众、品牌语气（可选）。
- 粘贴文本资料入库，按内容哈希去重；资料列表可查看、删除；删除项目级联处理其资料与内容。

### FR-2 一键生成（按内容类型驱动）
生成流程：资料分段 → 按主题/受众相关性选取 Top-K 证据片段 → 调用 LLM（要求仅输出 JSON、每条内容附引用来源 ID）→ 按类型 Schema 校验 → 入库。每种内容类型使用专属生成器与输出结构：

| 资产类型 | 输出结构（JSON） | 说明 |
|---|---|---|
| 公告 announcement | title、summary、body（正文段落）、actions（行动项列表）、source_ids | 面向正式发布通告 |
| FAQ faq | items[]：每项含 question、answer、source_ids | 问答对列表，可增删、排序、逐条编辑 |
| 海报文案 poster | headline、subhead、selling_points[]、cta、source_ids | 供前端模板渲染成海报 |

约束：
- 三类资产各走类型专用提示词模板（公告正式完整、FAQ 问题覆盖与技术准确、海报文案精炼有力）。
- 模型返回后按各类型 Schema 逐字段校验；字段缺失、三类不全或引用了未知来源 → 拒绝入库并返回明确错误。
- 拒答规则（合规底线）：项目无资料、证据得分不足、模型输出无依据内容时返回"需补充资料"，不产生任何半成品内容。
- LLM 通过配置化客户端接入（默认 DeepSeek，OpenAI 兼容），密钥仅存环境变量，接口永不回显。

### FR-3 编辑与状态
- 资产可直接覆盖编辑并保存。
- 状态机：`draft → pending_review → approved | rejected`；驳回需附意见，驳回后可改后重提。
- 编辑 approved 资产 → 状态自动回落 draft，审计日志记录修改前后内容快照。
- 编辑保存时同步校验并刷新依据引用，保证引用与内容一致。

### FR-4 审核工作台
- 审核者查看资产全文＋可展开的证据引用面板（显示每条引用对应的资料片段原文）。
- 通过/驳回（附意见）；仅 pending_review 状态可操作。

### FR-5 下载与发布
- 仅 approved 资产可下载：公告/FAQ/海报文案 → Markdown 或 HTML（带基础样式）。
- 仅 approved 资产可创建发布任务：适配器协议 `validate → publish → status`；首期为模拟渠道（记录任务、状态可查），后续可替换为真实渠道实现。

### FR-6 角色与审计
- 账号具备 editor 或 reviewer 角色；生成/编辑仅编辑者可用，审核仅审核者可用。
- 审计日志记录：生成、编辑（含内容快照）、审核结论、下载、发布，含操作者/时间/对象。

## 5. 非功能需求与合规要求

| 类别 | 要求 |
|---|---|
| 合规可追溯 | 每条内容可查依据；无依据不产出；审核、修改、下载、发布全操作审计 |
| 安全 | API 密钥仅环境变量；角色接口校验；密钥与资料不外泄至日志/响应 |
| 可靠性 | LLM 超时/网络错误返回可理解错误并支持重试；生成失败不留脏数据 |
| 性能 | 单次生成三类内容在 LLM 常规响应时间内完成（可接受十秒级）；列表页秒级加载 |
| 可维护 | 生成器协议化（测试可注入 Fake）；发布适配器协议化（可替换真实渠道） |

## 6. 范围与优先级（MoSCoW）

- **Must（P0）**：项目/资料管理（文本粘贴＋去重）；三类内容按类型专属结构生成；证据约束＋引用追溯＋不足拒答；覆盖式编辑＋approved 编辑回落；角色分离；审计日志；Markdown/HTML 下载；模拟发布适配器。
- **Should（P1）**：Markdown/TXT 文件上传；驳回意见流转通知；生成历史任务列表。
- **Could（P2）**：PDF/DOCX 解析；Chroma 向量检索；真实渠道适配器（企业微信/邮件）；海报 PNG 导出（html2canvas）。
- **Won't（本期不做）**：AI 图像生成、敏感词自动检查、多租户/多语言。

## 7. 方案架构（选定：方案 A 轻量全栈自建）

方案权衡结论：合规可控本质是流程与数据问题而非工具重量问题；轻量方案用最小代价建立合规骨架（门禁/追溯/审计），资料规模化后再演进知识库增强型。

技术栈：FastAPI + SQLAlchemy（async）+ SQLite｜Vue 3 + TypeScript + Element Plus + Vite｜DeepSeek（OpenAI 兼容，配置化可替换）。

```text
编辑（粘贴资料 / 触发生成 / 编辑内容）
        ↓
FastAPI API 层（角色校验 → 业务校验 → 审计落点）
        ↓
服务层：证据检索（分段/评分/Top-K） → 类型专用生成器（公告/FAQ/海报）
        ↓                                  ↓
DeepSeekGenerator（协议化，测试用 Fake）   校验器（Schema + 引用合法性）
        ↓
SQLAlchemy 存储（Project / Source / Asset / Review / Delivery / AuditLog）
        ↓
导出器（Markdown/HTML）＋ PublisherAdapter（模拟渠道）
```

模块边界（各自可独立测试）：
- `services/retrieval.py`：纯函数式资料分段与证据评分。
- `services/generation.py`：生成器协议、DeepSeek 客户端、类型化输出校验。
- `api/`：projects、sources、generation、assets（编辑＋审核）、delivery、audit。
- `export/`：Markdown/HTML 渲染。
- 前端：项目列表、资料中心、创作工作台（分类型编辑视图）、审核工作台、审计查询。

核心数据实体：`ContentProject`（主题/受众/语气）→ `Source`（粘贴资料＋哈希）→ `ContentAsset`（kind/status/content/citations）→ `ReviewRecord`（结论＋意见）→ `DeliveryTask`（适配器＋状态）→ `AuditLog`（全操作留痕）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LLM 幻觉事实 | 合规风险，审核者难以逐字核对 | 证据约束＋强制引用＋证据面板原文对照 |
| 审批后修改绕过审核 | 内容未经审核即流出 | approved 编辑即回落 draft＋审计快照 |
| LLM 输出不稳定（非法 JSON/缺字段） | 生成失败率高 | 严格 Schema 校验＋明确错误＋重试；Fake 生成器保障测试稳定 |
| 密钥/资料泄露 | 安全事故 | 密钥仅环境变量；日志脱敏；角色接口校验 |
| 覆盖式编辑丢内容 | 误改不可恢复 | 审计日志记录修改前后快照兜底 |

## 9. 成功标准与验收

1. 编辑者完成"建项目 → 贴资料 → 一键生成"闭环，产出三类结构化内容且各带来源引用。
2. 删除资料或资料与主题无关时，生成被拒答且无脏数据残留。
3. 编辑者不能审核；未通过内容的下载/发布接口返回 409。
4. approved 内容被修改后自动回落 draft，审计可查修改前后快照。
5. approved 内容可下载 Markdown/HTML，可创建模拟发布任务并可查状态。
6. 后端覆盖检索/生成/校验/状态机/导出/适配器契约测试；前端覆盖角色状态、失败重试与全流程。

## 10. 假设与依赖

- 资料以文本粘贴输入为主，单条资料规模在千字级，检索用轻量评分即可满足召回需求。
- LLM 依赖外部 DeepSeek 服务（OpenAI 兼容协议），可用性与速率受其约束；测试全程使用 Fake 替身，不调用外部服务。
- 发布渠道首期为记录型模拟实现，真实渠道接入时仅替换适配器实现，不改协议与上层流程。
- 海报视觉呈现由前端预设模板渲染，导出仅覆盖文案（Markdown/HTML）；PNG 导出列入 P2。
