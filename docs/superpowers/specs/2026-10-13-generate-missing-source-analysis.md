# content-workbench "一键生成"提示缺少资料问题分析

## 现象

在前端资料中心添加资料后，进入创作工作台点击「一键生成」，后端返回 422 `{"detail":"需补充资料"}`。

## 复现结果

我在本地启动 content-workbench 后端（`app.e2e_main:app`，FakeGenerator），用脚本模拟了三种资料内容：

| 资料内容 | 项目主题 / 受众 | 生成结果 |
|---|---|---|
| 本产品面向企业用户，支持 AI 内容生成与一键发布。 | AI 内容生成 / 企业用户 | ✅ 201，成功生成三类资产 |
| 今天天气不错，适合出去散步。 | AI 内容生成 / 企业用户 | ❌ 422 "需补充资料" |
| 你好。 | AI 内容生成 / 企业用户 | ❌ 422 "需补充资料" |

## 根因

后端 `POST /api/projects/{project_id}/generate` 的校验逻辑分为两层：

1. **资料非空校验**：查询该项目下的 `Source` 记录，若为空则返回 `"需补充资料"`。
2. **证据相关性校验**：调用 `services/retrieval.py` 的 `select_evidence`，按项目 `theme` 和 `audience` 作为关键词，对资料文本做句子切分和命中打分，只保留 `score > 0` 的片段。如果没有任何片段命中主题/受众关键词，同样返回 `"需补充资料"`。

`select_evidence` 的具体规则：
- 按空行和标点切分句子；
- 过滤长度小于 5 个字符的片段；
- 仅保留包含 `theme` 或 `audience` 关键词的片段；
- 返回 Top-K 作为生成证据。

因此，以下两种情况都会触发 `"需补充资料"`：
- 资料内容与项目主题/受众无关（如天气、无关文本）。
- 资料内容过短（如少于 5 个字符）。

## 可能的触发场景

### 场景 A：资料内容确实不相关
用户在资料中心粘贴了与项目主题/受众无关的内容，或内容太短。

### 场景 B：端口不一致导致请求发送到错误服务
当前 `127.0.0.1:8000` 存在幽灵占用（`netstat` 显示 LISTENING，但实际拒绝连接）。如果 PyCharm 启动的后端被迫使用了其他端口（如 8001），而前端 `vite.config.ts` 代理目标仍为 `http://127.0.0.1:8000`，则前端请求不会到达正确的后端，可能表现为旧服务、空服务或连接错误。

## 排查步骤

1. **确认后端实际监听端口**：
   ```powershell
   netstat -ano | findstr '127.0.0.1:8000'
   netstat -ano | findstr '127.0.0.1:8001'
   ```
   查看 PyCharm 启动命令中的 `--port` 参数。

2. **确认前端代理目标与后端端口一致**：
   检查 `content-workbench/frontend/vite.config.ts` 中的 `proxy.target`。

3. **查看后端日志**：
   点击「一键生成」时，后端应打印 `POST /api/projects/{id}/generate`。若日志无记录，说明请求未到后端，优先排查端口/代理。

4. **验证资料相关性**：
   在资料中心添加包含项目主题词和受众词的完整句子（如项目主题为「AI 内容生成」、受众为「企业用户」，资料应包含这些词）。

## 结论与建议

- 后端生成逻辑正常，符合「证据约束生成」的设计：只有与项目主题/受众相关的资料才会被用于生成。
- 若用户确认资料内容相关仍报错，应优先排查 **前端代理端口与后端启动端口是否一致**，当前 `8000` 端口存在幽灵占用，建议使用 `8001` 并同步修改 `vite.config.ts`。
- 长期来看，前端可以在「一键生成」失败时给出更明确的提示（如「资料与项目主题不相关，请补充相关资料」），但本次分析不涉及代码改动。
