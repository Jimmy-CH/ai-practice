# AI 内容运营 Agent 设计

## 目标与边界

在仓库根目录新增独立的 `content-ops-agent` 前后端应用。用户基于活动主题、产品文档、操作手册、CI/CD Webhook 事件与 Git Release/提交记录，一键生成可追溯的公告、FAQ 和海报；用户可编辑、版本化保存、提交人工审核，并在审核通过后下载或创建模拟发布任务。

首期不接入真实 CMS、微信公众号、企业微信或钉钉，仅提供可替换的发布适配器协议与模拟实现。不包含宣传视频生成。

## 架构

沿用现有项目的 FastAPI、Vue 3、TypeScript、Vite 与 SQLAlchemy 技术路线，并以独立应用保持内容运营与既有数据分析、知识库业务的边界。

```text
主题 / 文档 / CI/CD Webhook / Git 上下文
                 ↓
       来源标准化与项目知识索引
                 ↓
RAG 检索 + Content Orchestrator + LLM / 图像生成提供方
                 ↓
公告、FAQ、海报资产及不可变版本
                 ↓
编辑 → 提交审核 → 通过 / 驳回 → 下载 / 模拟发布
```

后端分为来源接入、知识服务、内容编排、资产版本、审核、导出和发布适配器模块。前端分为项目列表、来源中心、创作工作台、审核工作台和交付记录页面。

## 输入与知识溯源

`ContentProject` 是活动与资产的聚合根，包含主题、目标受众、品牌语气和状态。

`Source` 保存来源类型、原始内容或文件路径、外部事件 ID、解析状态、哈希和元数据。支持 PDF、DOCX、Markdown、TXT 文件；Webhook 保存经验证的 CI/CD 载荷；Git 集成读取指定仓库和范围内的 Release 与提交记录。

解析后的 `KnowledgeChunk` 记录文本、向量、来源 ID 与定位信息。生成时仅检索当前项目的片段；`AssetVersion` 保存使用的片段引用、提示词版本和模型参数，审核者可查看其生成依据。

## 内容编排与编辑

`ContentOrchestrator` 将已验证来源和检索证据交给内容类型专用生成器：

- 公告生成标题、摘要、正文、行动项与来源引用。
- FAQ 生成可增删、排序和编辑的问题/答案对及来源引用。
- 海报先生成标题、卖点、行动号召和视觉提示词，再调用图像提供方生成底图；用户可使用模板调整文本并预览。

任何资产编辑都创建新的 `AssetVersion`，旧版本不可修改。检索为空或证据不足时，任务返回“需补充资料”，不生成无依据事实。模型超时、提供方错误、文件解析错误均展示可理解状态并支持重试。

## 审核、导出与发布

资产状态机为 `draft → pending_review → approved | rejected`。驳回必须可附带评论；通过的特定版本才可导出和创建交付任务。审核、版本保存、下载和交付任务均写入审计日志。

公告和 FAQ 可下载为 Markdown、HTML、DOCX；海报可下载为 PNG、PDF。`PublisherAdapter` 定义 `validate`、`publish` 与 `status` 协议；首期的模拟适配器只记录任务输入、状态和结果，以便后续替换为真实渠道实现。

## 安全与权限

Webhook 使用 HMAC 签名、时间戳防重放和事件幂等键。Git 访问令牌加密保存且不经 API 回显。文件限定允许类型和大小，并在解析前进行安全扫描。角色至少区分编辑者与审核者；只有审核者可通过或驳回，只有已通过版本可交付。

## 验收标准与测试

- 用户可创建项目，导入主题、至少一种文档、模拟 CI/CD 事件和模拟 Git 发布上下文。
- 一次生成任务可产生公告、FAQ 与海报；每个结果展示来源引用且可编辑、版本化保存。
- 审核者可通过或驳回特定版本；未通过版本不可下载或交付。
- 通过版本可下载为约定格式，并创建可追踪的模拟发布任务。
- 后端覆盖来源导入、Webhook 幂等、检索引用、生成任务、版本审核状态机、导出与适配器契约测试。
- 前端覆盖项目创建、内容编辑、权限状态、失败重试和下载流程；端到端测试使用模拟 Git/CI 和样例文档贯通全流程。

## 实施假设

首期复用当前仓库已有的文档解析、向量检索、认证和 Agent 编排模式，但不直接耦合其业务模型。LLM 与图像生成提供方均通过配置化客户端接入，测试以可控的假实现替代外部调用。
